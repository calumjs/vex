`vex` is a command-line tool written in Rust that searches codebases and local engineering context by meaning, not by exact token. Single binary, no index, no server, no background process. Point it at a directory and ask a question in plain English; get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem

Keyword search — `grep`, `ripgrep`, editor search — assumes you already know the vocabulary the code uses. That assumption breaks on any non-trivial codebase. Searching for `retry` misses `fetch_with_retry`. Searching for `authentication` misses the PR discussion about session management. The context exists; the words differ; keyword search can't bridge the gap.

It gets worse as engineering context accumulates outside the code itself — GitHub issues, PR discussions, ADRs in Markdown. A single decision can span a dozen issues and multiple PRs from months ago. By the time someone needs to understand it, the vocabulary has diverged further still.

`vex` closes that gap by embedding query and candidates with a small local neural model and ranking by cosine similarity. The same query surface also covers synced GitHub issues and PRs when you've run `vex sync github`, so a question like "why did we change the auth flow" returns both the implementation and the discussions that motivated it, ranked together.

## How it works

The pipeline runs at query time — no index, no cache:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; files with zero overlap are dropped.
3. Chunk the top candidates — tree-sitter for Rust, Python, JS/TS, Go, C, C++, Java, C#; paragraph/sliding-window for prose and Markdown.
4. BM25 pre-filter narrows the pool to ~50 top candidates lexically.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That's what makes query-time embedding viable: a 19k-file monorepo returns in 729ms cold on a Snapdragon X Elite.

Key flags: `-k N` (result count), `-g "*.cs"` (glob filter), `--literal <term>` (keyword boost for vocabulary bridging), `-t 0.3` (similarity floor), `--json` (machine output), `--fast` (binary quantization for large trees), `--device npu` on supported hardware.

GitHub sync (`vex sync github`) materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/`. After a sync, every `vex` search includes that content automatically. Sync is incremental; a watermark in `.meta/sync-state.json` tracks the cursor. Use `--force` to re-fetch everything.

## Getting started

Requires [Rust](https://rustup.rs/). Install with:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup on Windows and Linux/macOS, and for the optional `/vex` Claude Code skill — a slash command that teaches agents synonym expansion, follow-up queries, and flow tracing. One `vex` call typically replaces 10–15 grep/glob/read calls from an agent.
