`vex` (`cargo install --git https://github.com/calumjs/vex`) is a command-line tool that searches code, documentation, and GitHub issues by meaning rather than keyword. No index, no background daemon, no setup beyond the initial binary. Cold queries on a 19,366-file monorepo return in 729ms on a Snapdragon X Elite.

```
vex "error handling with retries" src/
```

## The problem it solves

Engineering context is distributed. The *why* behind a feature spans GitHub issues, PR discussions, architecture docs, and Markdown files. A decision that lives across a dozen issues and three PRs is invisible to `grep` and `ripgrep` — search for "retry" and miss the issue titled "Resilience strategy for upstream timeouts"; search for "authentication" and miss the PR discussion about session management. There is a vocabulary gap between what you are looking for and how it was originally described; keyword search cannot bridge it.

This compounds in AI-assisted workflows. An agent that cannot surface the relevant context will repeat decisions, reintroduce bugs, and leave tribal knowledge tribal. If the context cannot be found, it cannot be used.

## How it works

Each query runs a six-step pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap — files with zero overlap are dropped.
3. **Chunk** top files using tree-sitter at function/class boundaries (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph splits for prose.
4. **BM25 pre-filter** narrows to the top ~50 candidates lexically.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That is what makes query-time embedding viable without pre-indexing.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/` with YAML frontmatter. After a sync, every `vex` search includes them alongside code — `vex "why did we change the auth flow"` returns the PR discussion, the architecture doc, and the implementation together, ranked by relevance. Sync is incremental via a watermark in `.meta/sync-state.json`; `--force` resets it. Credentials resolve in order: `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`.

## The `/vex` Claude Code skill

`.claude/skills/vex/SKILL.md` is a slash command for [Claude Code](https://claude.com/claude-code) that teaches the agent to use vex effectively — synonym expansion, follow-up queries, and flow tracing. Available automatically in any Claude Code session inside this repo; copy `SKILL.md` to `~/.claude/skills/vex/` for a global install. One `vex` call replaces 10–15 grep/glob/read calls from an agent.

## Notable flags

- `-k N` — result count (default 10)
- `-g "*.cs"` — constrain by glob
- `--literal <term>` — boost files containing a keyword before the neural ranker runs; repeatable; the vocabulary-gap escape hatch
- `-t 0.3` — minimum similarity floor
- `-C 5` — lines of context around each match
- `--json` — machine output
- `--fast` — binary quantization (~2× faster, less precise; for very large trees)
- `--device npu` — Snapdragon X Elite Hexagon NPU path

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup, Claude Code skill install, and the full options reference.
