`vex` is a Rust binary for semantic code search. No index, no server, no background process. Query in plain English; get ranked results from source files and synced GitHub issues in under a second.

## What it's for

Keyword search — `grep`, `ripgrep`, IDE search — requires knowing the vocabulary the code uses. That's often the problem. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR that redesigned session handling. The context exists; the naming is different.

`vex` bridges the vocabulary gap. It embeds your query and the candidate chunks with `all-MiniLM-L6-v2` (384 dimensions, INT8 quantized via ONNX Runtime) and ranks by cosine similarity. If you've run `vex sync github`, the same search also covers your GitHub issues and PRs — implementation and the discussion that motivated it, together, ranked by relevance.

## How it works

Each search runs a six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; drop files with no overlap.
3. Chunk the top 200 files — tree-sitter at function/class boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, and C#; paragraph splits for everything else.
4. BM25 pre-filter narrows to ~50 candidates.
5. Embed query and candidates with the local ONNX model.
6. Rank by cosine similarity, return top-k.

Steps 2–4 eliminate more than 99% of chunks before the neural model sees anything — that's why no pre-indexing is needed. On a 19,366-file monorepo (Snapdragon X Elite, cold), a query returns in 729 ms.

Useful flags: `-k N` for result count, `-g "*.rs"` for glob filter, `--literal <term>` to boost a specific keyword alongside the semantic score, `-t 0.3` for a similarity floor, `--json` for scripting, `--fast` for binary quantization on very large trees.

## GitHub sync

`vex sync github` materializes issues and PRs as local Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/`. After sync, every `vex` search includes them automatically. Credentials are read from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN` — only at sync time; search runs entirely locally over the materialized files.

Subsequent syncs are incremental (watermark in `.meta/sync-state.json`). Use `--force` to re-fetch everything.

## Claude Code skill

The repo ships a `/vex` slash command in `.claude/skills/vex/SKILL.md`. Install it globally or use it in-repo. The skill instructs Claude to expand queries with synonym `--literal` hints, run follow-up queries from different angles, and trace code flow from results. One `vex` call typically replaces 10–15 grep/glob/read calls from an agent.

## Getting started

Requires Rust. Install with:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized) downloads automatically on first run. [See the README](https://github.com/calumjs/vex) for PATH setup and the optional Claude Code skill install.
