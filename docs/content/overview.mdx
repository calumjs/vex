`vex` is a command-line tool for semantic search over code and GitHub issues. No index, no server, no background process. Point it at a directory, ask a question in plain English, get ranked results in under a second.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, and related code — not by matching the words "error" or "retry", but by meaning.

## The problem

More engineering context lives outside the code than in it. The *why* behind a feature is spread across GitHub issues, PR discussions, design docs, and markdown files that were once Slack threads. A single decision might span a dozen issues, three PRs, and an ADR.

`grep` and `ripgrep` can't help here. Search for "retry" and you miss the issue titled "Resilience strategy for upstream timeouts". Search for "authentication" and you miss the PR discussion about session management. There's a vocabulary gap between what you're looking for and how it was originally described. Keyword search can't bridge it.

This matters more as AI tools like Claude Code take on navigation tasks. If the context can't be found, it can't be used — decisions get repeated, bugs get reintroduced, tribal knowledge stays tribal.

## How it works

Each query runs a short pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`
2. Score files by keyword overlap — files with zero matches are dropped
3. Chunk the top files using tree-sitter (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph splitting for prose
4. BM25 pre-filter narrows to ~50 candidates
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime
6. Rank by cosine similarity; return top-k

Steps 2–4 drop more than 99% of chunks before the neural model runs. That's what makes query-time embedding viable: a 19,000-file monorepo returns in 729ms cold on a Snapdragon X Elite. No pre-indexing. No cache.

## GitHub sync

`vex sync github` pulls issues and PRs down as local Markdown files under `~/.local/share/vex/sources/github/`. After that, every `vex` search includes them alongside code, ranked by relevance. Search for "why did we change the auth flow" and get the PR discussion, the architecture doc, and the implementation in one result list.

Credentials resolve from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN`. Subsequent syncs are incremental — the watermark lives in `.meta/sync-state.json`.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup on Windows and Unix, and for the full option reference.

A `/vex` Claude Code skill ships with the repo (`skills/vex/SKILL.md`). Install it globally or use it in-repo — it teaches Claude synonym expansion, follow-up queries, and flow tracing. One `vex` call typically replaces 10–15 grep/glob/read calls from an agent.
