`vex` is a Rust CLI for semantic code search — no index, no server, no background daemon. Point it at a directory (or a GitHub issue archive), ask a question in plain English, and get cosine-ranked results in under a second.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, and similar symbols, ranked by vector similarity — not by whether the string "retry" appears in them.

## The problem

`grep` and `ripgrep` assume you know the vocabulary the code uses. You often don't. A search for "retry" misses `fetch_with_retry`. A search for "authentication" misses the PR discussion titled "Resilience strategy for upstream timeouts." The reasoning exists; the words don't match.

The gap compounds with AI-assisted development. Claude Code, Cursor, and similar tools rely on the context they can find. If `grep` can't surface a relevant file, it stays outside the agent's context window, and decisions get repeated or bugs get reintroduced.

`vex` closes the gap by embedding query and candidates at query time with `all-MiniLM-L6-v2` (384-dim, INT8 quantized, ~23 MB) via ONNX Runtime. A BM25 pre-filter drops >99% of chunks before the neural model runs, which is what makes query-time embedding viable: cold search on a 19k-file monorepo runs in 729ms on a Snapdragon X Elite.

## Searching code and GitHub together

`vex sync github` materializes issues and PRs as local Markdown under `~/.local/share/vex/sources/github/owner/repo/`. After that, every `vex` search automatically includes them. A query for "why did we change the auth flow" returns the PR discussion and the implementation side by side, ranked by relevance.

Sync is incremental — subsequent runs only fetch items updated since the last watermark in `.meta/sync-state.json`. Credentials (via `gh auth token` or `GITHUB_TOKEN`) are only needed during sync; search runs entirely locally.

## The pipeline

```
query ─► keyword score ─► tree-sitter chunk ─► BM25 pre-filter ─► embed ─► rank
```

1. Walk files in parallel (`.gitignore`- and `.vexignore`-aware).
2. Score by keyword overlap with the query; discard files with zero overlap.
3. Chunk top files — tree-sitter at function/class boundaries for Rust, Python, JS/TS, Go, C, C++, Java, C#; paragraph/sliding-window for prose.
4. BM25 narrows to the top ~50 candidates.
5. Embed query and candidates with ONNX Runtime.
6. Return top-k by cosine similarity.

Notable dials: `-k N` (result count), `-g "*.cs"` (glob filter), `--literal <term>` (keyword boost before neural ranking), `-t 0.3` (similarity floor), `--fast` (binary quantization for very large trees), `--device npu` (Snapdragon QNN backend).

## Getting started

Requires Rust:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup.

A `/vex` [Claude Code](https://claude.com/claude-code) skill ships in `skills/vex/SKILL.md`. It teaches Claude synonym expansion, follow-up queries, and flow tracing — one `vex` call typically replaces 10–15 grep/glob/read calls from an agent.
