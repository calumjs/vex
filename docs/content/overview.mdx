`vex` is a Rust CLI that runs semantic search across a codebase and its GitHub history at query time — no index, no background process, results in under a second.

```
vex "error handling with retries" src/
```

## The problem

`grep` and `ripgrep` operate on vocabulary. If you know the exact word the code uses, they work; if you don't, they miss. `vex "resilience strategy"` returns `fetch_with_retry`, `CircuitBreakerPolicy`, and the ADR that motivated them — none of which contain the search term.

The gap widens when the context lives outside the code. The *why* behind a feature is often in a PR discussion titled differently from anything in the source. `vex sync github` materializes issues and PRs as local Markdown; after that, every `vex` query automatically includes them alongside code, ranked together.

## Pipeline

Each query runs two stages: a cheap lexical pass that drops >99% of candidates, then a neural ranking pass on the survivors.

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap with the query — zero-overlap files are discarded.
3. **Chunk** the top 200 files using tree-sitter at function/class boundaries (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph/sliding-window for other text.
4. **BM25 pre-filter** narrows to ~50 candidates lexically.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8-quantized) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Benchmarks on Snapdragon X Elite (12-core Oryon): 468ms on a 585-file .NET codebase; 729ms on a 19k-file monorepo. Both cold, no cache.

## Flags worth knowing

- `-k N` — result count (default 10)
- `-t SCORE` — minimum similarity floor (e.g. `-t 0.3`)
- `-g GLOB` — restrict to matching files (e.g. `-g "*.cs"`)
- `--literal TERM` — hybrid mode: keyword-boost files before neural ranking, repeatable (`--literal lock --literal mutex`)
- `--fast` — binary quantization; ~2× faster on very large trees at lower precision
- `--device npu` — Hexagon NPU path on Snapdragon X Elite via QNN
- `-C N` — context lines around each match
- `--json` — structured output for scripting

## GitHub sync

```bash
vex sync github           # auto-detects repo from git remote
vex sync github --force   # re-fetch everything, ignore watermark
```

Synced items land under `~/.local/share/vex/sources/github/<owner>/<repo>/` as Markdown with YAML frontmatter. Subsequent syncs are incremental (watermark in `.meta/sync-state.json`). Credentials resolve in order: `gh auth login`, `GITHUB_TOKEN`, `GH_TOKEN`. Credentials are only used during sync; search runs locally.

## Claude Code skill

The `/vex` skill (`~/.claude/skills/vex/`) teaches Claude to use semantic search effectively — synonym expansion, follow-up queries, flow tracing. One `vex` call typically replaces 10–15 grep/glob/read calls from an agent.

## Install

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads on first run. Add `~/.cargo/bin` to PATH (Linux/macOS) or `%USERPROFILE%\.cargo\bin` (Windows) after installing.
