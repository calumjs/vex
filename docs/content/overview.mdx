`vex` (**Vector Examine**) is a Rust command-line tool that searches code and GitHub issues by meaning rather than keyword. No pre-built index, no background process — embed at query time and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem

Keyword search assumes you know the vocabulary the code uses. It rarely works out that way. `grep "retry"` misses `fetch_with_backoff`. `grep "authentication"` misses the PR discussion about session handling. The connection is there; the words diverge; `grep` cannot cross that gap.

The problem compounds when engineering context is spread across code, GitHub issues, PR comments, and architecture docs. A single design decision can span a dozen issues, three PRs, and an ADR written months earlier. No keyword query recovers that coherently.

## How it works

Each invocation runs a short pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Keyword-score files; drop any with zero query-term overlap.
3. Chunk top candidates using tree-sitter (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or sliding-window for prose.
4. BM25 pre-filter narrows to ~50 candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 discard more than 99% of chunks before the model runs — that is why query-time embedding is viable. A 19k-file monorepo returns cold in 729ms on a Snapdragon X Elite.

## GitHub issue search

Run `vex sync github` once to pull issues and PRs down as local Markdown. Subsequent searches automatically include them alongside code, so one query can surface the implementation, the PR that introduced it, and the issue that motivated it — all ranked together.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. An optional `/vex` Claude Code skill is included in the repo — it teaches Claude to use vex effectively (synonym expansion, follow-up queries, flow tracing), replacing ten-to-fifteen grep/glob/read calls per agent invocation.
