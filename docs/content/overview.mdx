`vex` is a command-line tool for semantic code search — written in Rust, distributed as a single binary, no index, no background process. Point it at a directory with a natural-language query; get ranked results under a second.

```
vex "error handling with retries" src/
```

## The problem it solves

Keyword search assumes you already know the vocabulary the code uses. On any non-trivial codebase, you often don't. `rg "retry"` misses `fetch_with_retry`. `grep "authentication"` misses the PR discussion about session management. The context exists; the words differ; `grep` can't bridge the gap.

The problem compounds when context is spread across issues, design docs, and PR discussions — none of which a code search tool reaches. On a growing codebase, or in an AI-assisted workflow where an agent is navigating unfamiliar code, the cost of missing context is decisions repeated, bugs reintroduced, tribal knowledge staying tribal.

## Pipeline

Each query runs a short pipeline:

1. Walk files (parallel, `.gitignore`-aware).
2. Score files by keyword overlap; drop files with zero overlap.
3. Chunk top-200 files with tree-sitter (Rust, Python, JS/TS, Go, C, C++, Java, C#) or prose splitting.
4. BM25 pre-filter → top ~50 candidates.
5. Embed query + candidates via ONNX Runtime (`all-MiniLM-L6-v2`, 384-dim, INT8 quantized).
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model runs. That is what makes query-time embedding viable without a pre-built index. Benchmarked on Snapdragon X Elite (12-core ARM64):

| Codebase | Files | Chunks | Time |
|---|---|---|---|
| Small (.NET app) | 585 | 3,227 | **468ms** |
| Large (monorepo) | 19,366 | 35,579 | **729ms** |

No pre-indexing. No cache. Cold search, every time.

## GitHub sync

`vex sync github` pulls issues and PRs as Markdown into `~/.local/share/vex/sources/github/owner/repo/`. After that, every `vex` query automatically includes them alongside code results. Incremental sync via `.meta/sync-state.json`; `--force` resets the watermark. Credentials resolve from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN` — used only during sync, not at query time.

## Claude Code skill

vex ships with a `/vex` Claude Code skill (`.claude/skills/vex/`) that instructs the agent on synonym expansion, follow-up queries, and flow tracing. One `vex` call typically replaces 10–15 grep/glob/read calls in an agent session.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads on first run. [See the README](https://github.com/calumjs/vex) for PATH setup, sync setup, and the Claude Code skill install.
