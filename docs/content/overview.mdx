`vex` is a Rust CLI for semantic search over code and GitHub issues. `cargo install --git https://github.com/calumjs/vex`, ask a question in plain English, get ranked results in under a second. No pre-built index, no background process, no server.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, `CircuitBreakerPolicy` — matches that are semantically related to "retry" even when the word doesn't appear in the chunk.

## The query pipeline

Six stages, every run:

1. Walk files (`.gitignore`- and `.vexignore`-aware, parallel)
2. Keyword-score each file against the query; skip files with zero overlap
3. Chunk the top-200 files — tree-sitter at function/class boundaries for supported languages, paragraph/sliding-window for prose
4. BM25 pre-filter → ~50 lexical candidates
5. Embed query + candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime
6. Cosine similarity ranking → top-k results

Steps 2–4 discard >99% of chunks before the neural model sees anything. That eliminates the need for pre-indexing: a 585-file .NET project returns in 468ms, a 19k-file monorepo in 729ms, both on a Snapdragon X Elite — cold, every time.

## Code and GitHub discussions in one search

`vex sync github [owner/repo]` pulls issues and PRs down as local Markdown with YAML frontmatter under `~/.local/share/vex/sources/github/`. After sync, every `vex` search spans code and GitHub context in a single ranked result list. Subsequent syncs are incremental via a watermark in `.meta/sync-state.json`; `--force` resets it.

```bash
# Find the PR discussion, the ADR, and the implementation — together
vex "why did we change the auth flow" ~/.local/share/vex/sources/github/calumjs/vex/
```

Credentials for sync resolve in order: `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`. Search is always local.

## Claude Code skill

The `/vex` skill (`skills/vex/SKILL.md`) teaches Claude Code to use semantic search effectively: synonym `--literal` expansion, multi-angle follow-up queries, flow tracing across call sites. One `vex` call replaces 10–15 grep/glob/read calls from an agent, reducing token spend and context-window pressure.

Or clone this repo — the skill loads automatically in any in-repo session.

## Language support

Tree-sitter chunking (function/class boundaries): Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. All other text files fall back to paragraph/sliding-window chunking.

Key flags: `-k N` (result count), `-g "*.ext"` (glob filter), `--literal <term>` (keyword boost before neural ranking), `-t 0.3` (similarity floor), `-C 5` (context lines), `--json` (machine output), `--fast` (binary quantization, ~2× faster on very large trees), `--device npu` on supported hardware.
