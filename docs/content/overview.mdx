`vex` is a Rust CLI for semantic code search — embed a natural-language query, rank results by cosine similarity against your source files and synced GitHub issues, and get answers in under a second. No index, no server, no background process.

## The problem

Keyword search assumes you know the vocabulary the code uses. Often you don't. A search for `retry` misses `fetch_with_retry`. A search for `authentication` misses the PR discussion about session management. The context exists; the words are different; `ripgrep` can't bridge the gap.

This is worse when AI tools are doing the searching. An agent navigating a codebase with `grep` and `read` burns through context window making a dozen narrowing calls before finding the right file. `vex` makes the call semantic so it lands on the first try.

A concrete scenario: a bug surfaces in a resilience path. The implementation is in `src/client.rs`. The design rationale is in a GitHub issue from four months ago. `rg "retry"` finds neither. `vex "error handling with retries"` finds both — code and discussion ranked together.

## How it works

Each query runs a six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`
2. Score files by keyword overlap — zero-overlap files are dropped before anything else runs
3. Chunk survivors via tree-sitter at function/class boundaries (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph splitting for prose
4. BM25 pre-filter to the top ~50 candidates lexically
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime
6. Rank by cosine similarity, return top-k

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That is why pre-indexing isn't needed: the funnel is narrow enough that query-time embedding lands under a second even on 19,000-file repositories.

GitHub issues and PRs can be materialized as local Markdown with `vex sync github`. After that, every `vex` search includes them automatically alongside code — implementation and the discussions that motivated it, side by side, ranked by relevance to the query.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized) downloads on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup, hardware options (`--device npu` on Snapdragon X Elite, `--fast` for binary quantization on very large trees), and the full option reference.

A Claude Code skill ships in `.claude/skills/vex/`. Install it globally to add the `/vex` slash command, which teaches Claude synonym expansion, follow-up queries, and flow tracing — one semantic call instead of ten `grep`/`read` cycles.
