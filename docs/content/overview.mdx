`vex` is a Rust CLI binary (`~/.cargo/bin/vex`) that runs semantic search across code directories and synced GitHub issues at query time. No index, no server, no background daemon — point it at a directory, ask in plain English, get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem

`grep` and `ripgrep` assume you know the vocabulary the code uses. On any non-trivial codebase, you often don't. A search for `retry` misses `fetch_with_retry`. A search for `authentication` misses the PR discussion about session management. The context exists; the words differ; keyword search can't bridge the gap.

The mismatch compounds in AI-assisted workflows. Agents navigating a codebase with grep/glob/read only see context that matches keywords — absent matches means absent context, which means decisions get re-made and bugs get reintroduced.

## How it works

Each query runs a fixed six-step pipeline:

1. Walk files respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; drop files with no overlap.
3. Chunk the top 200 files — tree-sitter boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#; paragraph/sliding-window for everything else.
4. BM25 pre-filter narrows to the top ~50 candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model runs. That's what makes query-time embedding viable: on a 19,366-file monorepo, cold latency is 729ms on a Snapdragon X Elite.

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/{owner}/{repo}/`, then every subsequent search includes them automatically. A query like "why did we change the auth flow" returns the PR discussion alongside the implementation, ranked together.

## Flags

`-k N` for result count, `-g "*.cs"` to constrain by glob, `--literal mutex` for a keyword boost, `-t 0.3` for a similarity floor, `--json` for machine output, `--fast` for binary quantization on very large trees, `--device npu` on supported hardware.

## Getting started

`cargo install --git https://github.com/calumjs/vex` installs the binary. The embedding model (~23 MB, INT8 quantized) downloads on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup on Windows and Linux/macOS.

The repo ships a `/vex` Claude Code skill (`skills/vex/`) — a slash command that teaches agents to use semantic search effectively (synonym expansion, follow-up queries, flow tracing). One `vex` call typically replaces ten-to-fifteen grep/glob/read calls from an agent. See the [README](https://github.com/calumjs/vex#2-install-the-claude-code-skill-optional) for install instructions.
