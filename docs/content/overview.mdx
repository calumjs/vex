`vex` is a command-line tool written in Rust for semantic search over code, docs, and GitHub issues. Single binary, no index, no background process. Point it at a directory and a natural-language query; it returns ranked results in under a second.

```
vex "error handling with retries" src/
```

Query-time embedding means results are always current — there is nothing to rebuild when the code changes.

## The problem

Keyword search assumes you already know the vocabulary the code uses. On any non-trivial codebase, you often don't. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR discussion about session management. The context exists; the words are different.

This compounds as codebases grow and AI tools like Claude Code try to navigate them. If the context can't be found by the agent, it can't be used — decisions get repeated, bugs get reintroduced, tribal knowledge stays tribal.

## The pipeline

```
  query ──► walk → keyword-score → chunk → BM25 → embed → cosine rank → top-k
```

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Keyword-score**: files with zero keyword overlap are dropped.
3. **Chunk** the top 200 files — tree-sitter for code (function/class boundaries), paragraph/sliding-window for prose and Markdown.
4. **BM25 pre-filter** narrows to ~50 candidates.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model runs. That's what makes query-time embedding viable: 585 files in 468ms, 19,366-file monorepo in 729ms on a Snapdragon X Elite.

## Supported languages (tree-sitter chunking)

Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Other file types fall back to paragraph chunking — vex works on any text.

## GitHub sync

`vex sync github` materializes issues and PRs as local Markdown under `~/.local/share/vex/sources/github/owner/repo/`. After sync, every `vex` query searches them alongside code. Incremental by default (watermark in `.meta/sync-state.json`); `--force` resets it.

Credentials resolve in order: `gh auth token` → `GITHUB_TOKEN` → `GH_TOKEN`. Credentials are only used during sync; search runs locally.

## Key flags

| Flag | Effect |
|---|---|
| `-k N` | Return top-N results (default: 10) |
| `-g "*.cs"` | Constrain by glob |
| `--literal <TERM>` | Boost files containing keyword before neural ranking |
| `-t 0.3` | Floor similarity score |
| `-C 5` | Lines of context around match |
| `--json` | Machine-readable output |
| `--fast` | Binary quantization — faster, slightly less precise |
| `--device npu` | Use Hexagon NPU on supported hardware |

## Install

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. Add `~/.cargo/bin` to PATH if not already there.
