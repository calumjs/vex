`vex` is a command-line tool written in Rust that searches code and engineering context by meaning rather than by token. No index, no server, no background process — point it at a directory, ask a question in plain English, and get ranked results in under a second.

## The problem

More and more engineering context lives outside the code. The *why* behind a feature is spread across GitHub issues, PR discussions, design docs, and Slack threads — a single decision might span a dozen issues, three PRs, and an ADR, and three months later nobody remembers where the reasoning lives.

`grep` and `ripgrep` can't help. You search for `retry` and miss the issue titled "Resilience strategy for upstream timeouts". You search for `authentication` and miss the PR discussion about session management. There's a vocabulary gap between what you're looking for and how it was originally described, and keyword search can't bridge it.

This matters more as teams rely on AI tools to navigate codebases. If the context can't be found, it can't be used — decisions get repeated, bugs get reintroduced, and tribal knowledge stays tribal.

## How it works

Each query runs a short pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; skip files with zero overlap.
3. Chunk the top files — tree-sitter (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) for code at function/class boundaries; paragraph/sliding-window for prose and Markdown.
4. BM25 pre-filter narrows to the top ~50 candidates lexically.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 discard more than 99% of chunks before the neural model runs. That is why query-time embedding is viable: a 19,000-file monorepo returns cold in 729ms on a Snapdragon X Elite.

## GitHub sync

Run `vex sync github` once to materialize your issues and PRs as local Markdown. After that, every `vex` query automatically includes them alongside code — so searching "why did we change the auth flow" surfaces the PR discussion, the architecture doc, and the implementation together, ranked by relevance.

Sync is incremental via a watermark in `.meta/sync-state.json`. Credentials (GitHub CLI token or `GITHUB_TOKEN`) are used only during sync; search runs entirely locally over the materialized files.

## AI-assisted workflows

vex ships with a `/vex` slash command for [Claude Code](https://claude.com/claude-code) that teaches the agent how to use semantic search effectively — synonym expansion, follow-up queries, and flow tracing. One `vex` call replaces 10–15 grep/glob/read calls from an agent, saving tokens and context window.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup, GitHub sync configuration, and the full CLI reference.
