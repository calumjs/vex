`vex` is a Rust CLI for semantic search across code, documentation, and synced GitHub issues. Single binary, no index, no background daemon. Point it at a directory, ask a question in plain English, get ranked results under a second.

```
vex "error handling with retries" src/
```

## The problem

Keyword search — `grep`, `ripgrep`, most editor search — requires you to already know what vocabulary the code uses. Often you don't. `grep "retry"` misses `fetch_with_retry`. `grep "authentication"` misses the PR discussion about session handling. The context exists; the words don't match; keyword search can't bridge the gap.

This friction compounds as codebases grow and AI tooling (Claude Code, Copilot) tries to navigate them. If context can't be retrieved, it can't be used — decisions repeat, bugs resurface, tribal knowledge stays tribal.

## How it works

Each query runs a six-step pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap — files with zero overlap are skipped.
3. **Chunk** the top 200 files via tree-sitter (function/class boundaries) for supported languages (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#), or paragraph/sliding-window for prose.
4. **BM25 pre-filter** narrows to the top ~50 candidates.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity, return top-k.

Steps 2–4 discard over 99% of chunks before the neural model sees anything. That is what makes query-time embedding viable: a 19,366-file monorepo returns cold in 729ms on a Snapdragon X Elite.

Useful dials: `-k N` (result count), `-g "*.cs"` (glob filter), `--literal <term>` (keyword boost before neural ranking), `-t 0.3` (similarity floor), `--json` (machine output), `--fast` (binary quantization for very large trees), `--device npu` (Snapdragon Hexagon NPU path).

## GitHub issues as searchable context

`vex sync github` pulls issues and PRs down as local Markdown under `~/.local/share/vex/sources/github/owner/repo/`. After that, every `vex` query automatically includes them alongside code. Search for "why did we change the auth flow" and get the PR discussion, the architecture doc, and the implementation — together, ranked by relevance. Sync is incremental; credentials only needed at sync time, not at search time.

## Getting started

Requires Rust. Install with:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. An optional `/vex` Claude Code skill ships in `.claude/skills/vex/SKILL.md` — copy it to `~/.claude/skills/vex/` for global availability. The skill teaches Claude synonym expansion, follow-up queries, and flow tracing; one `vex` call typically replaces 10–15 grep/glob/read calls from an agent.

[Full install instructions and PATH setup in the README](https://github.com/calumjs/vex#install).
