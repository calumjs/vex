`vex` is a command-line tool that searches code, docs, and GitHub issues by meaning, not by token. A single Rust binary: no index, no server, no daemon. Point it at a directory, ask a question in plain English, and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## What it solves

Keyword search assumes you already know the vocabulary the code uses. On any non-trivial codebase, you often don't. `grep "retry"` misses `fetch_with_backoff`. `rg "authentication"` misses the issue titled "Session management: RFC". The context exists; the words differ; BM25 can't cross that gap.

The problem compounds in AI-assisted workflows. An agent doing `grep → read → grep` across a large repo burns tokens fast and still misses context in differently-worded issues or PR discussions. `vex` closes both gaps — vocabulary and location — in a single query.

## How it works

Each query runs a six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Keyword-score files — drop any with zero query-term overlap.
3. Chunk top files with tree-sitter (function/class boundaries for Rust, Python, JS, TS, Go, C, C++, Java, C#) or paragraph splitting for prose.
4. BM25 pre-filter narrows to ~50 candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model sees anything — that is what makes query-time embedding viable. A 19k-file monorepo returns in 729ms on a Snapdragon X Elite, cold, no cache.

Run `vex sync github` once to pull issues and PRs down as local Markdown into `~/.local/share/vex/sources/github/owner/repo/`. After that, every `vex` search includes them automatically alongside code, ranked by the same pipeline.

Common flags: `-k N` for result count, `-g "*.cs"` to constrain by glob, `--literal <term>` for vocabulary-bridging keyword boosts, `-t 0.3` for a similarity floor, `--json` for machine output, `--fast` for binary quantization on very large trees.

## Getting started

Install via Cargo:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and platform-specific instructions.

The repo ships a `/vex` [Claude Code](https://claude.com/claude-code) skill (`skills/vex/SKILL.md`). Copy it to `~/.claude/skills/vex/` for global use across projects. The skill teaches Claude synonym expansion, follow-up queries, and flow tracing — one `vex` call typically replaces 10–15 grep/read calls from an agent.
