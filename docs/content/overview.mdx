`vex` is a Rust CLI that searches a codebase by meaning, not keywords. Single binary, no index, no background process. Query time is under a second on most codebases because the pipeline pre-filters aggressively before the neural model runs.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, and similar — even when the query words don't appear verbatim in the code.

## The problem it solves

Keyword search assumes you already know the vocabulary the code uses. On real codebases you often don't. `rg "retry"` misses `fetch_with_backoff`. `grep "authentication"` misses the PR discussion titled "Resilience strategy for upstream timeouts." The context exists; the vocabulary diverges; `grep` can't cross that gap.

This gets worse when AI tools are involved. If Claude Code can't locate relevant code and discussions, it can't reason about them — decisions get repeated, bugs get reintroduced, and institutional knowledge stays opaque.

`vex` addresses this by embedding query and candidates with a local neural model at query time (all-MiniLM-L6-v2, INT8 quantized, ~23 MB). A BM25 pre-filter narrows candidates to the top ~50 chunks before the model scores anything, so "no index" stays sub-second even on large trees.

## Usage shape

CLI, single query argument, optional path argument:

```
vex "database connection pooling"
vex "authentication middleware" src/
vex "race conditions" --literal lock --literal mutex
```

`--literal <TERM>` boosts files containing a specific keyword before ranking — the escape hatch when you already know part of the vocabulary. `--json` outputs structured results for scripting.

GitHub issues and PRs participate in search after `vex sync github`: synced items land as Markdown under `~/.local/share/vex/sources/github/owner/repo/` with YAML frontmatter, and every subsequent `vex` query includes them automatically. Search for "why did we change the auth flow" and get the PR discussion alongside the implementation.

The `/vex` Claude Code skill teaches Claude how to use `vex` effectively — synonym expansion, follow-up queries from different angles, flow tracing. The explicit intent: one `vex` call replaces 10–15 grep/glob/read calls from an agent.

## Pipeline

```
"retry logic" ──► 1. Walk files (.gitignore-aware, parallel)
                  2. Keyword-score files; drop zero-overlap
                  3. Chunk top 200 (tree-sitter for code, paragraph for prose)
                  4. BM25 pre-filter → top ~50 candidates
                  5. Embed query + candidates (ONNX, INT8, 12 cores)
                  6. Cosine similarity → ranked top-k
```

Steps 2–4 eliminate >99% of chunks before the neural model runs. This is what makes query-time embedding viable without a pre-built index.

Benchmarked on Snapdragon X Elite (12-core Oryon, ARM64): 468 ms on a .NET codebase (585 files, 3,227 chunks); 729 ms on a large monorepo (19,366 files, 35,579 chunks). No cache, cold search, every time.

Supported languages for tree-sitter chunking: Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Other file types fall back to paragraph/sliding-window chunking.

Requires Rust. Install with:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model downloads automatically on first run. See the [README](https://github.com/calumjs/vex#readme) for PATH setup, Claude Code skill install, and GitHub sync authentication.
