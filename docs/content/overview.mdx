## The problem

Keyword search (`grep`, `ripgrep`) requires vocabulary alignment between the query and the code. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR thread discussing session management. The gap widens when context lives outside code — in issues, PRs, and ADRs. `vex` closes it by embedding both sides.

## Pipeline

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score by keyword overlap; drop files with zero matches.
3. Chunk the top 200 files via tree-sitter (function/class boundaries) for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#; paragraph/sliding-window for prose and markdown.
4. BM25 pre-filter → top ~50 candidates.
5. Embed query + candidates with `all-MiniLM-L6-v2` (384-dim, INT8) via ONNX Runtime.
6. Cosine similarity → ranked top-k.

On a 19,366-file monorepo, cold search runs in 729ms on Snapdragon X Elite. No pre-indexing; no cache.

## GitHub sync

`vex sync github` materializes issues and PRs as local Markdown under `~/.local/share/vex/sources/github/`. After that, every `vex` query searches them automatically alongside code. Credentials resolve from `gh auth token` → `GITHUB_TOKEN` → `GH_TOKEN`; only used during sync, not search. Subsequent syncs are incremental (watermark in `.meta/sync-state.json`); use `--force` to re-fetch everything.

## Claude Code integration

The repo ships a `/vex` skill at `.claude/skills/vex/SKILL.md`. Install it globally or use it within the cloned repo. The skill teaches Claude to expand queries with `--literal` synonym hints, run follow-up queries from multiple angles, trace code flow after locating entry points, and combine `vex` with `grep` for precision. One `vex` call typically replaces 10–15 grep/glob/read calls, reducing token and context window spend.
