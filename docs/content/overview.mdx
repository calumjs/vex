`vex` (`~/.cargo/bin/vex`) is a Rust CLI for semantic code search — embed a natural-language query, get ranked source chunks back in under a second. No index, no daemon, no pre-build step. The binary walks files, runs a BM25 pre-filter, embeds query + candidates with `all-MiniLM-L6-v2` (INT8 quantized, via ONNX Runtime), and ranks by cosine similarity. Cold, every query.

## The problem it solves

Keyword search assumes you already know the vocabulary the code uses. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR titled "Resilience strategy for upstream timeouts". The reasoning behind a design spans GitHub issues, PR discussions, and ADRs — none of them sharing vocabulary with the implementation.

The gap widens with AI tooling. When Claude Code and similar agents use `grep`/`glob`/`read` loops to navigate unfamiliar code, unfindable context is invisible context. Decisions get repeated, bugs get reintroduced, tribal knowledge stays tribal.

## How it works

Each query runs a six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query — files with zero overlap are dropped.
3. Chunk the survivors using tree-sitter for code (function/class boundaries) or paragraph/sliding-window for prose.
4. BM25 pre-filter narrows the pool to ~50 candidates.
5. Embed query + candidates with `all-MiniLM-L6-v2` (384-dim, INT8) via ONNX Runtime on CPU.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model runs. This is why indexing isn't needed: the cold path finishes in 468–729ms on a Snapdragon X Elite across codebases from 585 to 19,366 files.

## GitHub sync

`vex sync github` pulls issues and PRs from the GitHub API into Markdown under `~/.local/share/vex/sources/github/owner/repo/`. Sync is incremental (watermark in `.meta/sync-state.json`; `--force` resets). After syncing, every `vex` query includes issues and PRs alongside source — search "why did we change the auth flow" and get the PR discussion, the ADR, and the implementation, ranked together.

Credentials resolve in order: `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`. Only used during sync; search runs locally over materialized Markdown.

## Language coverage

Tree-sitter chunking for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. All other text formats fall back to paragraph/sliding-window chunking.

## Claude Code integration

`/vex` slash command (`skills/vex/SKILL.md`) is available globally or per-project. It instructs Claude to expand queries with `--literal` hints for vocabulary bridging, run follow-up queries from multiple angles, read top results, and trace call graphs. One `vex` invocation typically replaces 10–15 `grep`/`glob`/`read` calls.

## Install

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and the optional `/vex` Claude Code skill.
