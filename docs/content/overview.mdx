`vex` is a Rust command-line tool for semantic search over code and engineering context. No index, no server, no background process — point it at a directory, ask a question in plain English, and get results back in under a second.

```
vex "error handling with retries" src/
```

## The problem

Keyword search assumes you already know the vocabulary the code uses. Often you don't. `rg "retry"` finds nothing for a function named `fetch_with_retry`. `rg "authentication"` misses the PR discussion that became the session-management subsystem. The vocabulary gap between what you are searching for and how it was originally written is invisible to `grep`.

The same gap affects AI-assisted workflows. If Claude Code cannot locate the relevant context — the ADR explaining a design decision, the issue that motivated a refactor — it cannot use it. Context that cannot be found cannot be applied; decisions get repeated and tribal knowledge stays tribal.

## How vex closes the gap

**Semantic scoring at query time.** vex embeds your query and each candidate chunk using `all-MiniLM-L6-v2` (384-dim, INT8 quantized via ONNX Runtime) and ranks results by cosine similarity. The model (~23 MB) downloads automatically on first run.

**BM25 pre-filter keeps it fast.** A lexical pass over the top candidate files eliminates >99% of chunks before the neural model runs. A cold search over a 19,366-file monorepo completes in 729 ms on Snapdragon X Elite — no pre-indexing required.

**Code and GitHub issues in one query.** `vex sync github` materialises issues and PRs as local Markdown files. Subsequent searches automatically include them alongside code — implementation and the discussions that motivated it, ranked together.

```bash
vex "why did we change the auth flow"
# → implementation file, architecture doc, PR discussion — ranked by relevance
```

**Vocabulary bridging with `--literal`.** Pin a keyword to boost files that contain it before the neural ranker runs — useful when you know the right term but want semantic ranking of the results:

```bash
vex "code that prevents race conditions" --literal lock --literal mutex
```

## Pipeline

Each query runs six steps:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`
2. Score files by query keyword overlap — zero-overlap files are dropped
3. Chunk the top 200 files: tree-sitter at function/class boundaries for supported languages, paragraph/sliding-window for prose
4. BM25 pre-filter narrows to the top ~50 candidates
5. Embed query and candidates (ONNX Runtime, INT8, multi-threaded)
6. Rank by cosine similarity, return top-k

Tree-sitter chunking is supported for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, and C#. All other file types fall back to paragraph/sliding-window chunking — vex works on any text file.

## Install

Requires [Rust](https://rustup.rs/):

```bash
cargo install --git https://github.com/calumjs/vex
```

Add `~/.cargo/bin` to `PATH` if it is not already on it. The embedding model downloads on first use.

## Claude Code skill

vex ships with a `/vex` skill for Claude Code that instructs the agent how to use semantic search effectively: synonym expansion, follow-up queries from different angles, and code-flow tracing. One `vex` call can replace 10–15 grep/glob/Read calls, saving tokens and context window.

**Global install:**

```bash
# Linux/macOS
mkdir -p ~/.claude/skills/vex
cp .claude/skills/vex/SKILL.md ~/.claude/skills/vex/

# Windows (PowerShell)
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills\vex"
Copy-Item .claude\skills\vex\SKILL.md "$env:USERPROFILE\.claude\skills\vex\"
```

Or clone the repo — the skill is automatically active in any Claude Code session inside it.

## GitHub sync

```bash
vex sync github                        # auto-detect repo from git remote
vex sync github calumjs/vex            # explicit owner/repo
vex sync github --include issues,prs   # issues and PRs (default)
vex sync github --state open           # only open items
vex sync github --labels bug,critical  # filter by labels
vex sync github --force                # ignore watermark, full re-sync
```

Credentials resolve in order: `gh auth token` → `GITHUB_TOKEN` → `GH_TOKEN`. Credentials are only used during sync; search runs locally over materialised Markdown. Incremental syncs are the default (watermark stored in `.meta/sync-state.json`).

Search synced content like any other directory:

```bash
vex "resilience strategy" ~/.local/share/vex/sources/github/calumjs/vex/
vex "login timeout"       ~/.local/share/vex/sources/github/calumjs/vex/issues/
vex "refactor auth"       ~/.local/share/vex/sources/github/calumjs/vex/prs/
```
