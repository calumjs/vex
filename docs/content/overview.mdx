`vex` is a command-line tool that searches code, documentation, and synced GitHub issues by meaning rather than by keyword. Single binary, no index, no server, no background daemon. Results arrive in under a second via query-time embedding against a local INT8-quantized neural model.

## The problem

Keyword search assumes you already know the vocabulary the code uses. On any non-trivial codebase, you often don't.

`rg "retry"` finds the string "retry". It misses `fetch_with_retry`, `CircuitBreakerPolicy`, and the GitHub issue titled "Resilience strategy for upstream timeouts" — all directly relevant, none sharing the keyword. The vocabulary gap widens as engineering context fragments across code, PR discussions, design docs, and issue threads. If the context can't be found, it can't be used: decisions get repeated, bugs get reintroduced, and tribal knowledge stays tribal.

This problem sharpens further for AI-assisted development. Claude Code and similar tools navigate a codebase through search. A tool that can only find what it already knows to look for hits the same wall.

## How it works

```
vex "error handling with retries" src/
```

That invocation runs a six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`
2. Score files by keyword overlap with the query; drop files with zero overlap
3. Chunk the top files — tree-sitter at function and class boundaries for Rust, Python, JS/TS, Go, C, C++, Java, C#; paragraph-window splitting for prose and Markdown
4. BM25 pre-filter narrows to ~50 candidates lexically
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime
6. Rank by cosine similarity, return top-k

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That pre-filtering is what makes query-time embedding viable without a pre-built index. Benchmarks on Snapdragon X Elite: a 585-file codebase completes in 468ms; a 19,366-file monorepo in 729ms — both cold, no cache.

**GitHub sync.** `vex sync github` materializes issues and PRs as local Markdown with YAML frontmatter. After that, every search automatically includes them alongside code. A query like `"why did we change the auth flow"` returns the PR discussion, the architecture doc, and the implementation, ranked together. Sync is incremental via a watermark in `.meta/sync-state.json`.

**Claude Code skill.** The repo ships a `/vex` skill (`skills/vex/SKILL.md`) that teaches Claude Code synonym expansion, follow-up queries, and flow tracing. One `vex` invocation replaces 10–15 grep/glob/read calls from an agent — a meaningful reduction in token usage and context window pressure.

## Getting started

Requires Rust. Install:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB) downloads automatically on first run. [See the README for PATH setup, GitHub sync auth, and the optional Claude Code skill install](https://github.com/calumjs/vex#install).
