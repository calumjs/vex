`vex` is a Rust CLI that searches code and engineering context by meaning rather than by token. A single binary, no pre-built index, no server. Point it at a directory or a set of synced GitHub issues, ask a question in plain English, and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem it solves

Keyword search breaks when the vocabulary of your query differs from the vocabulary of the code. `rg "retry"` returns `retry`. It does not return `fetch_with_retry`, `handle_failure`, or `CircuitBreakerPolicy` — the functions that actually implement the retry logic in a typical service. On any codebase large enough to forget, and on any project where the *why* lives in GitHub issues and PR discussions rather than inline comments, this gap compounds.

The problem sharpens when AI tools like Claude Code navigate your repo. If the relevant context can't be found, it can't be used — decisions get repeated, bugs get reintroduced, and tribal knowledge stays tribal. `vex` closes the gap by embedding query and candidates at query time, with no pre-built index required.

## How it works

Each query runs a six-step pipeline: walk files respecting `.gitignore` and `.vexignore`, keyword-score them, chunk the top files via tree-sitter (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph splitting for prose, BM25 pre-filter to the top candidates, embed both query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime, rank by cosine similarity.

Steps 2–4 eliminate > 99% of chunks before the neural model sees anything. That is what makes query-time embedding viable without a pre-built index. Benchmarked cold on a Snapdragon X Elite: 468ms on a 585-file .NET codebase, 729ms on a 19k-file monorepo.

`vex sync github` pulls issues and PRs down as local Markdown files. After that, every query automatically searches them alongside code — the implementation and the discussion that motivated it appear in the same ranked list. Credentials are resolved from `gh auth token` or `GITHUB_TOKEN`, and only used during sync; search runs entirely locally.

`vex` also ships with a `/vex` Claude Code skill that instructs the agent to expand queries with `--literal` hints for vocabulary bridging, run follow-up queries from different angles, and trace code flow from results. One `vex` call replaces 10–15 grep/glob/read calls, saving tokens and context window.

## Getting started

`cargo install --git https://github.com/calumjs/vex` installs the binary. The embedding model (~23 MB, quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and the optional Claude Code skill install.
