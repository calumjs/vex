`vex` is a Rust CLI that searches source code and GitHub issues by meaning rather than by token. Single binary, no daemon, no pre-built index. Queries return in under a second on repositories up to 20k files.

## What it solves

Keyword search assumes you already know the vocabulary the code uses. That assumption breaks down quickly. A search for `retry` misses `fetch_with_backoff`. A search for `auth` misses the PR that restructured session handling into three separate modules. The context exists in the repo; the terms don't align; `ripgrep` can't bridge the gap.

This matters more as codebases grow and as AI tools like Claude Code are asked to navigate them. If an agent can't locate the relevant context, it repeats decisions that were already made, reintroduces bugs that were already fixed, and mistakes old patterns for current ones.

## The pipeline

Each query runs six steps:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; files with zero overlap are dropped.
3. Chunk the top 200 files — tree-sitter at function/class boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#; paragraph/sliding-window for prose and other text formats.
4. BM25 pre-filter narrows to ~50 lexical candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime on CPU.
6. Rank by cosine similarity; return top-k.

Steps 2–4 discard more than 99% of chunks before the neural model runs. That is what keeps query-time embedding viable without a pre-built index: a 19k-file monorepo returns in 729ms cold on a Snapdragon X Elite (12-core Oryon, ARM64). No cache. No warmup.

## GitHub issues alongside code

`vex sync github` materializes issues and PRs as Markdown files under `~/.local/share/vex/sources/github/{owner}/{repo}/`, each with YAML frontmatter (number, state, labels, timestamps, inline comments). Sync is incremental via a watermark in `.meta/sync-state.json`; `--force` resets it.

After a sync, every `vex` query automatically includes the materialized files alongside code. A search for "why did we change the auth flow" returns the PR discussion, the architecture doc, and the implementation — ranked together by semantic similarity, not separated by source.

## The `/vex` Claude Code skill

The repo ships a Claude Code skill at `.claude/skills/vex/SKILL.md`. Copy it to `~/.claude/skills/vex/` and it is available as `/vex` in any Claude Code session. The skill instructs the agent to expand queries with synonym `--literal` hints, run follow-up queries from different angles, and trace code flow by chaining results into subsequent reads. In practice, one `/vex` invocation replaces 10–15 grep/glob/read tool calls.

## Getting started

Requires [Rust](https://rustup.rs/). Install with:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized `all-MiniLM-L6-v2`) downloads automatically on first run. For Claude Code integration, copy `.claude/skills/vex/SKILL.md` to `~/.claude/skills/vex/`. See the [README](https://github.com/calumjs/vex#install) for PATH setup and GitHub sync credentials.
