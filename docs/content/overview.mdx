`vex` is a Rust command-line tool that searches code and engineering context by meaning, not by keywords. No index, no background server — point it at a directory, ask a question in plain English, get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem it solves

Keyword search assumes you already know the vocabulary the code uses. A search for `retry` misses `fetch_with_retry`. A search for `authentication` misses the PR discussion about session management. The context exists; the words differ; `grep` can't bridge the gap.

The problem extends beyond the codebase itself. A decision's reasoning might live in a GitHub issue, a PR discussion, and an architecture doc — written months apart, under different search terms. `vex sync github` pulls issues and PRs down as local Markdown files, so every query automatically searches them alongside the source. The implementation and the discussion that motivated it come back together, ranked by relevance.

## How it works

Each query runs a short pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap. Files with no overlap are dropped.
3. **Chunk** the top files — tree-sitter for supported languages (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#), paragraph/sliding-window for prose.
4. **BM25 pre-filter** narrows the pool to the top candidates.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 eliminate more than 99% of chunks before the neural model sees anything. On a 19,366-file monorepo, cold search completes in 729 ms on a Snapdragon X Elite — fast enough that query-time embedding replaces pre-indexing entirely.

## Flags and options

The CLI exposes the standard dials: `-k N` for result count, `-g "*.cs"` to constrain by glob, `--literal mutex` to pin a keyword boost before neural ranking, `-t 0.3` to floor the similarity score, `--json` for machine output, `--fast` for binary quantization on very large trees, `--device npu` on supported hardware.

## Claude Code integration

vex ships with a `/vex` slash command for [Claude Code](https://claude.com/claude-code). It instructs the agent to use synonym `--literal` hints, run follow-up queries from different angles, and trace code flows from matching results. One `vex` call typically replaces ten to fifteen grep/glob/read calls, compressing both token spend and context noise.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

Requires [Rust](https://rustup.rs/). The embedding model (~23 MB, INT8 quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex) for PATH setup and GitHub sync configuration.
