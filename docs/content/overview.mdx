`vex` searches code and GitHub issues by meaning, not tokens. It is a single binary (`cargo install --git https://github.com/calumjs/vex`) with no index, no background daemon, no server. Point it at a directory, ask a question in plain English, and get ranked results in under a second.

## The problem it solves

`grep` and `ripgrep` require knowing the vocabulary the code uses. On a non-trivial codebase you often don't. A search for `retry` misses `fetch_with_retry`. A search for `authentication` misses the PR discussion about session handling. The context exists; the words are different.

The gap widens once engineering context is spread across GitHub issues, PR discussions, and architecture docs. `vex sync github` pulls those down as local Markdown, making every `vex` query search code and discussions together, ranked by relevance.

## What using it looks like

```bash
vex "error handling with retries" src/
```

Returns ranked code chunks — `fetch_with_retry` at 0.42, `handle_failure` at 0.39 — even though neither contains the word "retry." The pipeline uses BM25 pre-filtering to eliminate >99% of chunks before the neural model runs, which is why there is no pre-indexing step.

```bash
vex sync github calumjs/vex        # pull issues and PRs as local Markdown
vex "resilience strategy" .        # returns code + issue discussions together
```

Nine languages (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) chunk at function and class boundaries via tree-sitter. Other file types fall back to paragraph splitting.

A `/vex` skill for Claude Code ships at `.claude/skills/vex/SKILL.md`. It teaches the agent synonym expansion, follow-up queries, and flow tracing — one `vex` call replaces 10–15 grep/read calls in an agentic context.

## Getting started

Requires Rust ([rustup.rs](https://rustup.rs/)). [See the README for install and PATH setup](https://github.com/calumjs/vex#install). The embedding model (~23 MB, INT8 quantized) downloads on first run.
