## The problem

Engineering context scatters. The reasoning behind a feature lives across GitHub issues, PR discussions, design docs, and Slack threads — and keyword search can't bridge the gap between what you're looking for and how it was originally written. A search for `retry` misses `fetch_with_backoff`. A search for `authentication` misses the PR discussion about session management. The vocabulary diverges; the context exists but stays hidden.

This gap widens when codebases grow and AI tools like Claude Code need to navigate them. If the context can't be found, it can't be used.

## How vex works

Each query runs a short pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap — skip files with zero overlap.
3. Chunk the top files using tree-sitter at function/class boundaries (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#), or paragraph/sliding-window for prose.
4. BM25 pre-filter narrows to the top ~50 candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate more than 99% of chunks before the neural model runs. That is what makes query-time embedding fast enough to skip pre-indexing: a 19,366-file monorepo returns cold in 729ms on a Snapdragon X Elite.

## GitHub integration

Run `vex sync github` once to pull issues and PRs down as local Markdown. After that, every `vex` search includes them automatically alongside code, ranked by the same cosine similarity. A query for "why did we change the auth flow" returns the PR discussion, the architecture doc, and the implementation together.

Credentials (GitHub CLI, `GITHUB_TOKEN`, or `GH_TOKEN`) are only needed during sync. Subsequent syncs are incremental — only items updated since the last run are fetched.

## Common flags

| Flag | Effect |
|------|--------|
| `-k N` | Number of results (default 10) |
| `-g "*.cs"` | Constrain to files matching glob |
| `--literal mutex` | Pin a keyword boost (repeatable) |
| `-t 0.3` | Minimum similarity threshold |
| `--json` | Machine-readable output |
| `--fast` | Binary quantization — faster on very large trees |
| `--device npu` | NPU inference on supported hardware |

## Claude Code skill

vex ships with a `/vex` slash command for Claude Code. The skill teaches the agent to expand queries with synonym hints, run follow-up queries from different angles, and trace code flow — replacing ten-to-fifteen grep/glob/read calls with one `vex` call.

```bash
/vex how does the billing system handle retries
/vex "race conditions" --literal lock --literal mutex
```

## Install

```bash
cargo install --git https://github.com/calumjs/vex
```
