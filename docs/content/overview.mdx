`vex` is a Rust CLI that searches code and engineering context by meaning, not by keyword. No index, no server, no daemon — run it against any directory and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem

`grep` and `ripgrep` assume you already know the vocabulary the code uses. On a working codebase, you often don't. A search for `retry` misses `fetch_with_retry`. A search for `authentication` misses the PR discussion titled "Resilience strategy for upstream timeouts." The context is there; the words are different; keyword search can't bridge the gap.

The problem compounds when engineering decisions live outside the code — in GitHub issues, PR discussions, ADRs. Months later, nobody remembers where the reasoning is. AI tools like Claude Code make this worse: if they can't find the context, they reproduce the decision instead of inheriting it.

## How it works

Each query runs a fixed six-step pipeline:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap. Files with zero overlap are skipped entirely.
3. Chunk the top files using tree-sitter (function/class boundaries) for supported languages, or paragraph/sliding-window for prose.
4. BM25 pre-filter narrows to ~50 top candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime on CPU.
6. Rank by cosine similarity, return top-k.

Steps 2–4 eliminate more than 99% of chunks before the neural model runs. That is what makes query-time embedding viable without pre-indexing. Benchmarked on a Snapdragon X Elite: 468 ms cold on a 585-file .NET app, 729 ms on a 19,366-file monorepo.

Tree-sitter chunking is supported for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, and C#. Other file types fall back to paragraph splitting — vex works on any text.

### GitHub sync

`vex sync github` pulls issues and PRs down as local Markdown with YAML frontmatter. After that, every search automatically includes them alongside code. `vex "why did we change the auth flow"` returns the implementation and the discussion that motivated it, ranked together. Sync is incremental via a watermark in `.meta/sync-state.json`; `--force` resets it. Credentials are only required at sync time, not at search time.

### Claude Code integration

vex ships with a `/vex` Claude Code skill in `.claude/skills/vex/`. The skill teaches the agent how to use semantic search effectively: synonym expansion via `--literal`, follow-up queries from different angles, and flow tracing. One `vex` call replaces 10–15 grep/glob/read calls from an agent.

## Getting started

Install requires [Rust](https://rustup.rs/). The binary builds from source:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, INT8 quantized) downloads automatically on first run. No additional setup. For the Claude Code skill, copy `.claude/skills/vex/SKILL.md` to `~/.claude/skills/vex/` — or just open a session inside this repo.

See the [README](https://github.com/calumjs/vex#install) for PATH setup and the full options reference (`-k`, `-t`, `--literal`, `--fast`, `--device`, and more).
