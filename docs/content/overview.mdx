`vex` is a Rust CLI for semantic search over code, docs, and synced GitHub issues. Query in plain English; get ranked results in under a second. No index, no server, no background daemon.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, `CircuitBreakerPolicy`, and any design docs that describe the resilience strategy — even when none of them contain the word "retry". The gap between the vocabulary you search with and the vocabulary the code uses is the core problem `vex` solves.

## Pipeline

Each query runs five stages:

1. **Walk** — parallel file walk, `.gitignore`/`.vexignore`-aware.
2. **Score** — keyword overlap filter. Files with zero overlap are dropped entirely.
3. **Chunk** — tree-sitter chunking at function/class boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Paragraph/sliding-window fallback for prose and unknown file types.
4. **Pre-filter** — BM25 narrows the chunk pool to ~50 candidates.
5. **Embed + rank** — `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime. Cosine similarity over candidates; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model runs. That is what makes query-time embedding viable without a pre-built index.

Benchmarks on Snapdragon X Elite (12-core Oryon, ARM64):

| Codebase | Files | Chunks | Cold query |
|---|---|---|---|
| Small (.NET app) | 585 | 3,227 | **468ms** |
| Large (monorepo) | 19,366 | 35,579 | **729ms** |

## GitHub sync

`vex sync github [owner/repo]` pulls issues and PRs down as local Markdown files with YAML frontmatter, stored under `~/.local/share/vex/sources/github/`. After sync, those files participate in every `vex` search automatically — querying "why did we change the auth flow" returns the PR discussion and the implementation together, ranked by relevance.

Syncs are incremental via a watermark in `.meta/sync-state.json`; `--force` resets it. Credentials resolve in order: `gh auth token` → `GITHUB_TOKEN` → `GH_TOKEN`. Only needed during sync; search runs locally over materialized files.

## Claude Code integration

`.claude/skills/vex/SKILL.md` ships with the repo and is available as `/vex` in any Claude Code session within it. The skill instructs the agent to expand queries with synonym `--literal` hints for vocabulary bridging, run follow-up queries from multiple angles, read top results, and trace code flow. One `vex` call typically replaces 10–15 grep/glob/read calls, preserving context window.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. Add `~/.cargo/bin` to PATH.
