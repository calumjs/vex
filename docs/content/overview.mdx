`vex` is a command-line tool that searches code and engineering context by meaning, not by token. No index, no server, no background daemon. Point it at a directory, ask a question in plain English, and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem it solves

Keyword search assumes you already know the vocabulary the code uses. On any non-trivial codebase, you often don't. `rg "retry"` finds the word "retry"; it misses `fetch_with_retry`, `handle_failure`, and the GitHub issue titled "Resilience strategy for upstream timeouts." The context exists — the words are different — and `grep` can't bridge the gap.

Engineering context also lives outside the code. The *why* behind a feature is spread across GitHub issues, PR discussions, design docs, and notes that got pasted into a Markdown file. A single decision might span a dozen issues, three PRs, and an ADR — and months later, nobody remembers where the reasoning lives. Keyword search can't find it by meaning, because it doesn't understand meaning.

## How it works

Each query runs a tight pipeline:

1. Walk files respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query; drop files with zero overlap.
3. Chunk the top files — tree-sitter for supported languages (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#), paragraph/sliding-window for prose.
4. BM25 pre-filter narrows the pool to the top ~50 candidates lexically.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. Rank by cosine similarity; return top-k.

Steps 2–4 eliminate more than 99% of chunks before the neural model sees anything — that is why query-time embedding is viable without pre-indexing. A 19k-file monorepo returns cold in 729ms on a Snapdragon X Elite.

## GitHub sync

Run `vex sync github` once to pull issues and PRs down as local Markdown under `~/.local/share/vex/sources/github/`. After that, every `vex` query automatically includes them alongside the code. A search for "why did we change the auth flow" returns the PR discussion, the architecture doc, and the implementation — together, ranked by relevance.

Sync is incremental via a watermark in `.meta/sync-state.json`; `--force` resets it. Credentials (GitHub CLI, `GITHUB_TOKEN`, or `GH_TOKEN`) are only used during sync. Search runs entirely locally.

## Claude Code integration

vex ships with a `/vex` [Claude Code](https://claude.com/claude-code) skill that teaches agents to use semantic search effectively — synonym expansion, follow-up queries, flow tracing. One `vex` call typically replaces ten-to-fifteen grep/glob/read calls, saving tokens and context window on every non-trivial codebase navigation task.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and optional Claude Code skill installation.
