`vex` is a CLI written in Rust that searches code and engineering context by meaning. A single binary — no daemon, no index, no server. Point it at a directory and ask a question in plain English.

```
vex "error handling with retries" src/
```

Returns `src/client.rs:47 pub async fn fetch_with_retry` and `src/worker.rs:112 fn handle_failure` — not because the word "retry" appears in them, but because they're semantically close to the query.

## The vocabulary gap

Keyword search (`grep`, `ripgrep`) assumes you know the words the code uses. On any codebase of consequence, you often don't. The PR that introduced a resilience strategy might be titled "Upstream timeout handling," the implementing function might be `fetch_with_retry`, and the design doc discussing it might never contain the word "retry." All three exist; `grep "retry"` finds none of them.

`vex` closes the gap by embedding query and candidates at query time using a local neural model ([all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), 384-dim, INT8-quantized, via ONNX Runtime). A BM25 pre-filter eliminates >99% of chunks before the model runs — that's what makes query-time embedding viable without a pre-built index.

`vex sync github` materialises GitHub issues and PRs as local Markdown. After syncing, a single query can return an implementation, the PR that introduced it, and the issue that motivated it, ranked together by semantic relevance.

## How it works

Each query runs six steps:

1. Walk files in parallel, respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap with the query. Files with zero overlap are skipped.
3. Chunk the top 200 files — tree-sitter at function/class boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#; paragraph/sliding-window for everything else.
4. BM25 pre-filter narrows to ~50 candidates.
5. Embed query and candidates on CPU (ONNX Runtime, INT8, parallelised across threads).
6. Rank by cosine similarity; return top-k.

Benchmarked on Snapdragon X Elite: 468ms on a 585-file .NET app, 729ms on a 19,366-file monorepo. Cold search, no cache.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads on first run. Full install and PATH setup instructions are in the [README](https://github.com/calumjs/vex#install).

Key flags: `--literal <TERM>` boosts files containing a keyword before the neural step — useful for vocabulary bridging (`vex "race conditions" --literal lock --literal mutex`). `-k`, `-g`, `-t`, `--json`, `--fast`, and `--device npu` cover the remaining dials.

The repo ships a `/vex` [Claude Code](https://claude.com/claude-code) skill. Installing it teaches Claude synonym expansion, follow-up queries, and flow tracing — one `vex` call typically replaces 10–15 grep/glob/read calls in an agentic session.
