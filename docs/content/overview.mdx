## The problem

Keyword search assumes you know the vocabulary the code uses. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR about session management. The vocabulary gap grows as more context accumulates in GitHub issues, PRs, and design docs — sources `grep` doesn't reach at all.

The same gap affects AI-assisted workflows. If `vex` can't surface it, neither can Claude Code — and decisions get repeated, bugs get reintroduced, tribal knowledge stays tribal.

## Pipeline

```
  "retry logic" ──► walk → keyword-score → chunk → BM25 → embed → rank
```

1. **Walk** files in parallel, respecting `.gitignore` / `.vexignore`.
2. **Keyword-score** files; drop any with zero query-term overlap.
3. **Chunk** top-200 files using tree-sitter (Rust, Python, JS/TS, Go, C, C++, Java, C#) or paragraph/sliding-window for prose.
4. **BM25 pre-filter** narrows to ~50 candidates.
5. **Embed** query + candidates with `all-MiniLM-L6-v2` (384-dim, INT8) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the model runs — which is what makes query-time embedding viable. A 19k-file monorepo returns cold in 729ms on a Snapdragon X Elite.

## GitHub sync

`vex sync github` materializes issues and PRs as local Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/`. Subsequent syncs are incremental (watermark in `.meta/sync-state.json`). After that, every `vex` search includes them alongside code.

```bash
vex sync github                     # auto-detects repo from git remote
vex sync github --include issues,prs --state open
vex "why did we change the auth flow" ~/.local/share/vex/sources/github/calumjs/vex/
```

Credentials are resolved from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN` — only needed during sync.

## Claude Code skill

The repo ships a `/vex` skill at `.claude/skills/vex/SKILL.md`. Install it globally or point Claude Code at this repo. The skill teaches the agent to expand queries with `--literal` hints, run follow-up searches from different angles, and trace code flow. One `vex` call typically replaces 10–15 grep/glob/read calls, saving tokens and context.

## Key flags

| Flag | Effect |
|------|--------|
| `-k N` | Number of results (default 10) |
| `-g "*.cs"` | Restrict to glob-matched files |
| `--literal <term>` | Boost files containing this keyword (repeatable) |
| `-t 0.3` | Minimum similarity threshold |
| `-C 5` | Context lines around matches |
| `--json` | Machine-readable output |
| `--fast` | Binary quantization — less precise, ~2× faster on huge trees |
| `--device npu` | Use NPU on supported hardware (Snapdragon X Elite) |
