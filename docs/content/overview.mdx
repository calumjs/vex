`vex` is a single Rust binary (`cargo install`) that runs semantic search over a codebase at query time. No index. No background process. Point it at a directory, query in plain English, get ranked results in under a second.

## The problem

Keyword search has a vocabulary gap. `grep "retry"` misses `fetch_with_retry`. `rg "authentication"` misses a PR titled "Resilience strategy for upstream timeouts". The code and the context exist; the words are different.

This compounds on AI-assisted workflows. Claude Code navigates a codebase by searching it. When the right chunk doesn't surface, it doesn't get used — decisions get repeated, bugs get reintroduced, and tribal knowledge stays tribal.

## How it works

The pipeline at query time:

1. Walk files respecting `.gitignore` / `.vexignore`, in parallel.
2. Score files by keyword overlap with the query; drop files with zero overlap.
3. Chunk the top files using tree-sitter (function and class boundaries) for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Prose and Markdown fall back to paragraph/sliding-window splitting.
4. BM25 pre-filter narrows thousands of chunks to ~50 candidates lexically.
5. Embed query and candidates via [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) — 384-dim, INT8-quantized, ONNX Runtime, up to 12 threads.
6. Rank by cosine similarity, return top-k.

The BM25 pass eliminates >99% of chunks before the neural model runs. That's why cold search stays sub-second without an index: 468ms on a small .NET codebase (585 files), 729ms on a 19k-file monorepo — benchmarked on a Snapdragon X Elite (Oryon 12-core, ARM64), no cache.

## GitHub sync

Run `vex sync github` once to materialize issues and PRs as Markdown under `~/.local/share/vex/sources/`. After that, every `vex` search hits them alongside code — same binary, same ranking, no extra flags. Subsequent syncs are incremental; the watermark lives in `.meta/sync-state.json`.

Credentials resolve in order: `gh auth token`, then `GITHUB_TOKEN`, then `GH_TOKEN`. Only needed during sync; all search runs locally.
