## The problem

Engineering context is distributed. The *why* behind a feature lives in GitHub issues, PR discussions, design docs, and ADRs — not in the code itself. `grep` and `ripgrep` require you to already know the vocabulary: searching for "retry" misses the issue titled "Resilience strategy for upstream timeouts." Searching for "authentication" misses the PR discussion about session management. There is a vocabulary gap between what you're looking for and how it was described.

This matters more as AI-assisted workflows become standard. If the context can't be found, it can't be used by Claude Code, Copilot, or any other agent — and decisions get repeated, bugs get reintroduced, and tribal knowledge stays tribal.

## How vex closes the gap

```
                    ┌─────────────────────────────────────────┐
  "retry logic" ──► │  1. Walk files (.gitignore-aware)        │
                    │  2. Score files by keyword matches        │
                    │  3. Chunk top files (tree-sitter / prose) │
                    │  4. BM25 pre-filter → top candidates     │
                    │  5. Neural embed (ONNX, INT8, 12 cores)  │
                    │  6. Cosine similarity → ranked results    │
                    └─────────────────────────────────────────┘
```

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That is what makes query-time embedding viable without a pre-built index. On a Snapdragon X Elite: 585-file .NET app in **468ms**, 19,366-file monorepo in **729ms**, cold every time.

The embedding model is `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime. Tree-sitter chunking for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, and C#; paragraph/sliding-window for everything else.

## GitHub sync

`vex sync github` pulls issues and PRs down as local Markdown with YAML frontmatter. After that, every `vex` search includes them alongside code automatically:

```bash
vex sync github calumjs/vex          # pull issues + PRs
vex "why did we change the auth flow" # finds PR discussion + implementation together
```

Sync is incremental — a watermark in `.meta/sync-state.json` tracks what was last fetched. `--force` resets it. Credentials resolve via `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN`; only needed for sync, not for search.

## CLI surface

Key flags:

| Flag | Effect |
|---|---|
| `-k N` | Number of results (default 10) |
| `--literal <TERM>` | Boost files containing this keyword (repeatable) |
| `-t 0.3` | Floor similarity at 0.3 |
| `-g "*.cs"` | Constrain to glob |
| `-C 5` | Lines of context around match |
| `--fast` | Binary quantization — ~2x faster, less precise |
| `--device npu` | Hexagon NPU on Snapdragon X Elite |
| `--json` | Machine-readable output |

`--literal` is the vocabulary bridge: `vex "code that prevents race conditions" --literal lock --literal mutex` — the literal hint boosts the right candidates before the neural ranker scores them.

## Claude Code skill

vex ships with a `/vex` skill (`skills/vex/SKILL.md`) for Claude Code. Install it globally or clone this repo — it's auto-available inside any session in the worktree. The skill instructs the agent to expand queries with synonym `--literal` hints, run follow-up queries from different angles, and trace code flow. One `vex` call typically replaces 10–15 grep/glob/read calls.

```bash
# in Claude Code
/vex error handling in authentication
/vex "race conditions" --literal lock
```
