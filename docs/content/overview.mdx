`vex` is a Rust CLI binary (`~/.cargo/bin/vex`) that runs semantic search over code and GitHub issues at query time — no index, no server, no background process. Install with `cargo install --git https://github.com/calumjs/vex`.

```
vex "error handling with retries" src/
```

## The problem

`grep` and `rg` require vocabulary alignment. You search `retry`, you miss `fetch_with_retry`. You search `authentication`, you miss the PR titled "Resilience strategy for upstream timeouts." Engineering context — the *why* behind decisions — is spread across issues, PR discussions, design docs, and ADRs with different terminology than the code that implemented them. Keyword search can't bridge the gap. `vex` does.

## Pipeline

Each query runs six stages:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`
2. **Score** files by keyword overlap — drop files with zero overlap
3. **Chunk** top 200 files: tree-sitter at function/class boundaries for code; paragraph/sliding-window for prose
4. **BM25 pre-filter** narrows to ~50 candidates lexically
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8) via ONNX Runtime
6. **Rank** by cosine similarity, return top-k

Steps 2–4 eliminate >99% of chunks before the model sees anything. Cold query on a 19,366-file monorepo: 729ms on a Snapdragon X Elite.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/owner/repo/`. After sync, every `vex` call searches them automatically alongside code. Incremental — only fetches items updated since the last sync watermark (`.meta/sync-state.json`). Credentials via `gh auth token` or `GITHUB_TOKEN`.

## Claude Code skill

The `/vex` skill (`~/.claude/skills/vex/SKILL.md`) teaches Claude to use semantic search effectively: synonym expansion via `--literal`, follow-up queries from different angles, and flow tracing through call sites. One invocation replaces 10–15 grep/glob/read calls from an agent.

## Supported languages (tree-sitter)

Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Other file types fall back to paragraph/sliding-window chunking.
