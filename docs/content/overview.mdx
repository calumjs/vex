`vex` is a command-line tool written in Rust. It searches code and engineering context by meaning rather than by token: point it at a directory, ask a question in plain English, get ranked results in under a second. No index, no server, no background daemon.

## The problem it solves

Keyword search (`grep`, `rg`) requires knowing what vocabulary the code uses. On a non-trivial codebase, you often don't. Searching for `retry` misses `fetch_with_backoff`. Searching for `authentication` misses the PR discussion titled "Session management refactor." The context exists; the words don't match.

This compounds when teams rely on AI tools like Claude Code to navigate their codebases. If relevant context can't be found, it can't be used — decisions get repeated, bugs get reintroduced, tribal knowledge stays tribal.

## How it works

Each query runs a six-step pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap with the query — files with zero overlap are dropped.
3. **Chunk** the top 200 files at function/class boundaries (tree-sitter for Rust, Python, JS/TS, Go, C, C++, Java, C#) or paragraph splits for prose and Markdown.
4. **BM25 pre-filter** narrows to the top ~50 candidates lexically.
5. **Embed** query and candidates using [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity and return top-k results.

Steps 2–4 eliminate >99% of chunks before the neural model runs. This is why vex doesn't require pre-indexing — it's fast enough to embed at query time.

## GitHub sync

`vex sync github` pulls your repo's issues and PRs down as local Markdown files. After that, every `vex` query includes them alongside source files automatically. A search for "why did we change the auth flow" can surface the PR discussion, the architecture doc, and the implementation together, ranked by semantic relevance.

Credentials resolve in order: `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`. Only used during sync. Search runs locally over materialized Markdown in `~/.local/share/vex/sources/github/`.

Subsequent syncs are incremental — only items updated since the last watermark are fetched. Use `--force` to re-sync everything.

## Claude Code skill

vex ships a `/vex` slash command (`skills/vex/SKILL.md`) that teaches Claude how to use semantic search effectively: synonym expansion via `--literal`, multi-angle follow-up queries, and code flow tracing. One `vex` invocation replaces 10–15 grep/glob/read calls.

Install globally by copying `SKILL.md` to `~/.claude/skills/vex/`, or clone this repo — the skill is available in any Claude Code session within it.
