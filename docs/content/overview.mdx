## The vocabulary gap

Keyword search assumes you know the vocabulary the code uses. On any real codebase, you often don't. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR discussion about session management. The context exists — the words differ, and `grep` can't bridge it.

This compounds with AI-assisted workflows: if an agent like Claude Code can't locate context through grep, it can't use it. Decisions get repeated, bugs reintroduced, tribal knowledge stays tribal.

## Pipeline

Each query runs a six-step pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`
2. **Score** files by keyword match count — files with zero overlap are dropped immediately
3. **Chunk** the top 200 files — tree-sitter at function/class boundaries for Rust, Python, JS, TS, Go, C, C++, Java, C#; paragraph/sliding-window for everything else
4. **BM25 pre-filter** narrows to the top ~50 candidates lexically
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime
6. **Rank** by cosine similarity, return top-k

Steps 2–4 eliminate >99% of chunks before the model runs. That's what makes query-time embedding viable without pre-indexing: 19,366 files return cold in 729ms on a Snapdragon X Elite.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/owner/repo/` with YAML frontmatter. After sync, every `vex` query includes them alongside code — search for "why did we change the auth flow" and get the PR discussion, the ADR, and the implementation together.

Sync is incremental via a watermark in `.meta/sync-state.json`; `--force` re-fetches everything. Credentials resolve in order: `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`. Only needed during sync — search is local.

## Claude Code skill

`/vex` ships as a Claude Code slash command (`skills/vex/SKILL.md`). The skill instructs Claude to use synonym expansion via `--literal`, run follow-up queries from different angles, and trace call flows through results. One `vex` call typically replaces ten-to-fifteen grep/glob/read calls, reducing context-window pressure in agentic workflows.

