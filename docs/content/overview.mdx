`vex` is a Rust CLI that searches code and GitHub issues by meaning rather than keyword. No index, no server — it embeds at query time using a local ONNX model, runs a BM25 pre-filter, and returns ranked results in under a second.

```bash
vex "error handling with retries" src/
```

## The problem it solves

`grep` and `ripgrep` assume you know the vocabulary the code uses. On a real codebase you often don't. Searching for "retry" misses `fetch_with_retry`. Searching for "authentication" misses the PR that called it "session handling." The context exists; the terms don't match.

This compounds for AI-assisted workflows. Tools like Claude Code pull in context to reason about — if the relevant code or discussion can't be found, it won't be surfaced, and decisions get repeated.

## What using it looks like

Point `vex` at a directory and ask a question in plain English:

```bash
vex "database connection pooling" src/
vex "config parsing" -k 3            # top 3 results
vex "race conditions" --literal lock  # boost files containing "lock"
```

GitHub issues and PRs can be synced once with `vex sync github`. After that, every search covers code and discussions together — each issue or PR becomes a local `.md` file with YAML frontmatter (`type`, `number`, `title`, `state`, `labels`) and is ranked alongside source files.

Internally: walk files → keyword-score → tree-sitter chunk → BM25 narrow to ~50 candidates → embed with [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) (INT8, ONNX Runtime) → cosine rank. Steps 2–4 eliminate >99% of chunks before the model runs — that's what makes sub-second searches on a 19k-file monorepo work without an index.

Benchmarked on Snapdragon X Elite (12-core Oryon): 468ms on a 585-file .NET app, 729ms on a 19,366-file monorepo.

## Getting started

Requires Rust. Install from source:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex) for PATH setup, all CLI flags, and `vex sync github` options.

A Claude Code skill ships in `.claude/skills/vex/`. Copy it to `~/.claude/skills/vex/` to get the `/vex` slash command across all projects.
