`vex` is a Rust CLI that searches code, docs, and synced GitHub issues by semantic similarity. No pre-built index. No background process. The embedding runs at query time against a BM25-filtered candidate set, so cold searches on a 19,000-file monorepo land under a second.

```bash
vex "error handling with retries" src/
```

Returns `fetch_with_retry` in `src/client.rs` and `handle_failure` in `src/worker.rs` without either file containing the word "retry."

## The problem it solves

Keyword search assumes you already know the vocabulary. On non-trivial codebases, you often don't — `rg "retry"` misses `fetch_with_backoff`, and `rg "authentication"` misses the PR titled "Resilience strategy for upstream timeouts." The reasoning behind decisions is spread across GitHub issues, PR threads, and design docs; the words used there rarely match what you search for later.

`vex sync github` pulls issues and PRs into local Markdown files. After that, every `vex` query searches code and GitHub context together, ranked by relevance. The same invocation finds the implementation and the discussion that motivated it.

## Pipeline

```
query → walk files → keyword score → chunk → BM25 → embed → cosine rank
```

1. Walk files in parallel; respect `.gitignore` and `.vexignore`.
2. Score files by keyword overlap; drop files with zero overlap.
3. Chunk the top 200 files — tree-sitter boundaries for Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#; paragraph splitting for prose.
4. BM25 pre-filter narrows to ~50 candidates.
5. Embed query + candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime on CPU.
6. Rank by cosine similarity.

Steps 2–4 eliminate >99% of chunks before the neural model runs. Cold search, no cache:

| Codebase | Files | Time |
|---|---|---|
| Small (.NET app) | 585 | 468 ms |
| Large (monorepo) | 19,366 | 729 ms |

`--literal <term>` boosts files containing a keyword before ranking — bridge vocabulary gaps when the term is partially known (`vex "concurrency bugs" --literal mutex --literal lock`). `--fast` enables binary quantization for ~2× speed on very large trees.

## Claude Code skill

`vex` ships a `/vex` slash command (`skills/vex/SKILL.md`) that teaches Claude Code how to search effectively: synonym expansion, multi-angle follow-up queries, flow tracing. One `vex` call typically replaces ten-to-fifteen grep/glob/read calls. Copy `SKILL.md` to `~/.claude/skills/vex/` for global access, or leave it in the repo for project-scoped use.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB, quantized) downloads on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and GitHub sync auth.
