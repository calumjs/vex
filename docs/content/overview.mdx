`vex` is a Rust CLI (`cargo install --git https://github.com/calumjs/vex`) that searches a codebase and its GitHub history by meaning, not keywords. No index to build, no daemon to run — cold queries complete in under a second.

## The problem

Keyword search assumes you know the vocabulary the code uses. You often don't. `rg "retry"` misses `fetch_with_retry`. `rg "authentication"` misses the PR titled "Resilience strategy for upstream timeouts." The context exists; the words are different; grep can't bridge the gap.

This matters more as teams lean on tools like Claude Code to navigate large repos. If the context can't be found, it can't be used — decisions get repeated, bugs get reintroduced, and knowledge stays tribal.

## How it works

Each invocation runs a five-stage pipeline:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap — files with zero overlap are dropped before any embedding happens.
3. **Chunk** the top candidates at semantic boundaries: tree-sitter function/class boundaries for Rust, Python, JS/TS, Go, C, C++, Java, C#; paragraph splits for everything else.
4. **Pre-filter** with BM25 to a ~50-chunk shortlist.
5. **Embed** query and candidates with [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) (384-dim, INT8, ONNX Runtime), rank by cosine similarity.

Steps 2–4 discard >99% of chunks before the neural model runs. That's what makes the indexless design viable — the BM25 funnel is cheap enough that cold embedding at query time stays sub-second even on monorepos.

Benchmarks on Snapdragon X Elite (12-core ARM64):

| Codebase | Files | Chunks | Latency |
|---|---|---|---|
| Small (.NET app) | 585 | 3,227 | 468ms |
| Large (monorepo) | 19,366 | 35,579 | 729ms |

## GitHub issues in the same search

Run `vex sync github` once. It materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/` with YAML frontmatter. After that, every `vex` query searches them alongside source files. Search for "why did we remove the cache" and get the PR discussion, the ADR, and the implementation together — ranked by relevance.

Sync is incremental via a watermark in `.meta/sync-state.json`. Credentials are read from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN` in that order, and only needed at sync time.

## The Claude Code skill

`/vex` ships as a Claude Code skill in `.claude/skills/vex/`. The skill teaches the agent to use vex effectively: synonym expansion via `--literal`, multi-angle follow-up queries, and flow tracing. A single `vex` call replaces 10–15 grep/glob/read calls, saving tokens and context window.

Copy `SKILL.md` to `~/.claude/skills/vex/` for global availability, or just work inside the repo — the skill is active in any Claude Code session there.
