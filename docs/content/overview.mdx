`vex` is a Rust CLI that runs semantic search over a directory tree without pre-indexing. Query at query time: it walks files, keyword-scores, BM25-filters, then embeds with `all-MiniLM-L6-v2` (INT8/ONNX) and ranks by cosine similarity. Cold latency on a 19k-file monorepo: 729ms on Snapdragon X Elite.

```
vex "error handling with retries" src/
```

Returns `fetch_with_retry`, `handle_failure`, and `CircuitBreakerPolicy` even if none contain the literal word "retry" — the vocabulary gap is closed by the embedding, not the query.

## The problem

Keyword search assumes you know the vocabulary the code uses. On real codebases you often don't. Worse, the *why* behind decisions is scattered across GitHub issues, PR discussions, design docs, and markdown files that were once Slack threads. A feature's rationale might span a dozen issues, three PRs, and an ADR — six months later, nobody knows where it lives.

`grep` misses `fetch_with_retry` when you search for "retry". `ripgrep` misses the session-management PR when you search for "authentication". The context exists; the words are different. `vex` closes that gap.

## Pipeline

Each query runs six steps in sequence:

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** files by keyword overlap — files with zero overlap are dropped immediately.
3. **Chunk** the top 200 files using tree-sitter for supported languages (Rust, Python, JS/TS, Go, C, C++, Java, C#) or paragraph/sliding-window for prose and unknown types.
4. **BM25 pre-filter** narrows the chunk pool to ~50 lexical candidates.
5. **Embed** query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime.
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 discard >99% of chunks before the model runs — that's what makes query-time embedding viable at sub-second latency with no pre-built index.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/owner/repo/`, with YAML frontmatter. Every subsequent `vex` search includes them automatically — implementation code and the discussions that motivated it, ranked together in one result set.

Sync is incremental; the watermark lives in `.meta/sync-state.json`. Auth resolves in order: `gh auth token` → `GITHUB_TOKEN` → `GH_TOKEN`. Credentials are only needed for sync; local search runs entirely offline.

## Claude Code skill

`skills/vex/SKILL.md` registers a `/vex` slash command that teaches Claude Code to use semantic search effectively — synonym expansion via `--literal` hints, follow-up queries from different angles, flow tracing through results. One `vex` call typically replaces 10–15 grep/glob/read calls from an agent.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. Add `~/.cargo/bin` to `PATH` if it isn't already.
