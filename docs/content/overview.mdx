## The problem it solves

`grep` and `ripgrep` find the word you give them. They can't bridge the gap between the vocabulary you're using and the vocabulary the codebase uses. Search for "retry" and miss `fetch_with_retry`. Search for "authentication" and miss the PR discussion that settled the session strategy.

The gap compounds at scale. Engineering context is spread across GitHub issues, PR review threads, design docs, and markdown files — none of which will use exactly the words you think of later. `grep` has no way in.

`vex` closes that gap by embedding your query and the candidate chunks with a local neural model ([all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), INT8 quantized, 384-dim) and ranking by cosine similarity. It also searches GitHub issues and PRs when you've run `vex sync github` — the implementation and the discussion that motivated it appear together, ranked by relevance.

## How the pipeline works

```
  query ──► walk → keyword-score → chunk → BM25 filter → embed → rank
```

1. **Walk** files in parallel, respecting `.gitignore` and `.vexignore`.
2. **Score** by keyword overlap with the query — zero-overlap files are dropped.
3. **Chunk** the top files. Tree-sitter at function/class boundaries for Rust, Python, JS, TS, Go, C, C++, Java, C#; paragraph splitting for prose and Markdown.
4. **BM25 pre-filter** narrows to ~50 candidates lexically.
5. **Embed** query and candidates via ONNX Runtime on CPU (or `--device npu` on Snapdragon X Elite).
6. **Rank** by cosine similarity; return top-k.

Steps 2–4 eliminate >99% of chunks before the neural model sees anything. That is what makes query-time embedding viable without an index: a 19,366-file monorepo returns in 729ms cold.

## GitHub sync

```bash
vex sync github              # auto-detects repo from git remote
vex sync github calumjs/vex  # explicit
```

Materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/<owner>/<repo>/`. After syncing, every `vex` search automatically includes them. Sync is incremental — subsequent runs only fetch items updated since the last watermark (`.meta/sync-state.json`); `--force` resets it.

Credentials are resolved in order from `gh auth token`, `GITHUB_TOKEN`, `GH_TOKEN`. Only needed during sync; search is entirely local.

## Claude Code skill

The repo ships a `/vex` skill at `.claude/skills/vex/SKILL.md`. Install globally and it's available in every Claude Code session:

```bash
mkdir -p ~/.claude/skills/vex && cp .claude/skills/vex/SKILL.md ~/.claude/skills/vex/
```

The skill instructs Claude to expand queries with synonym `--literal` hints, run follow-up queries from multiple angles, read top results and trace the code flow, and layer in grep for exact-match follow-up. One `vex` call typically replaces 10–15 grep/glob/read calls in an agent session.

## Getting started

Requires [Rust](https://rustup.rs/). Install the binary:

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB quantized) downloads automatically on first run. See the [README](https://github.com/calumjs/vex#install) for PATH setup and all CLI options.
