## The vocabulary gap

`rg "retry"` finds the token "retry". It misses `fetch_with_retry`, `handle_failure`, `CircuitBreakerPolicy`, and the issue titled "Resilience strategy for upstream timeouts" — all semantically equivalent, none lexically matching. The gap between query vocabulary and code vocabulary grows with codebase age and team size; AI navigation tools amplify the problem when the context can't be found.

`vex` closes the gap by embedding the query and candidate chunks at query time with a small local neural model (`all-MiniLM-L6-v2`, 384-dim, INT8 quantized, ~23 MB) running via ONNX Runtime.

## Pipeline

Walk → keyword-score → tree-sitter chunk → BM25 pre-filter → ONNX embed → cosine rank. Steps 2–4 eliminate >99% of chunks before the model runs, making query-time embedding fast enough to skip pre-indexing.

```
                ┌─────────────────────────────────────────┐
"retry logic" ► │  1. Walk files (.gitignore-aware)        │
                │  2. Score files by keyword matches        │
                │  3. Chunk top files (tree-sitter / prose) │
                │  4. BM25 pre-filter → top candidates     │
                │  5. Neural embed (ONNX, INT8, 12 cores)  │
                │  6. Cosine similarity → ranked results    │
                └─────────────────────────────────────────┘
```

Benchmarked on Snapdragon X Elite (ARM64, 12-core Oryon): 468ms on a 585-file .NET codebase, 729ms on a 19,366-file monorepo. No warmup, no cache.

Tree-sitter chunking: Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#. Other text falls back to paragraph/sliding-window splitting.

Key flags: `-k N` (result count), `-g "*.cs"` (glob filter), `--literal <term>` (keyword boost, repeatable), `-t 0.3` (similarity floor), `--json` (machine output), `--fast` (binary quantization), `--device npu|cpu|auto`.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown files under `~/.local/share/vex/sources/github/<owner>/<repo>/`. Every subsequent `vex` query includes them alongside local code files. Auth resolves from `gh auth token`, `GITHUB_TOKEN`, or `GH_TOKEN` — only needed at sync time; search is local.

```bash
vex sync github                        # auto-detect repo from git remote
vex sync github --include issues,prs   # issues + PRs
vex sync github --state open           # open issues only
vex sync github --force                # ignore watermark, re-fetch everything
```

Incremental syncs skip unchanged items via a watermark in `.meta/sync-state.json`.

## Claude Code skill

`skills/vex/SKILL.md` is a `/vex` slash command for Claude Code. It teaches the agent to expand queries with synonym `--literal` hints, run follow-up queries from multiple angles, and trace code flow through top results. One `vex` call typically replaces 10–15 `grep`/`glob`/`Read` calls.

## Getting started

```bash
cargo install --git https://github.com/calumjs/vex
```

The embedding model (~23 MB) downloads on first run. Add `~/.cargo/bin` to your `PATH`. See the [README](https://github.com/calumjs/vex#install) for platform-specific PATH setup.
