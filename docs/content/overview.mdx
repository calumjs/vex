`vex` is a Rust CLI (`cargo install --git https://github.com/calumjs/vex`) that runs semantic search over source code and GitHub issues at query time — no pre-built index, no daemon, no server. Point it at a directory and get ranked results in under a second.

```
vex "error handling with retries" src/
```

## The problem

Keyword search assumes you already know the vocabulary the code uses. You often don't. `grep "retry"` misses `fetch_with_retry`. `grep "authentication"` misses the PR thread titled "Resilience strategy for upstream timeouts." The code and the discussion both exist; the words are different; grep can't bridge the gap.

Engineering context compounds the problem. Design rationale spreads across GitHub issues, PR descriptions, and ADRs. Three months later, nobody remembers which issue motivated which change, and decisions get repeated or reversed without the underlying reasoning surfacing.

## How it works

Each query runs a five-stage pipeline:

1. Walk files respecting `.gitignore` and `.vexignore`.
2. Score files by keyword overlap — drop files with zero overlap.
3. Chunk the top files using tree-sitter (Rust, Python, JavaScript, TypeScript, Go, C, C++, Java, C#) or paragraph splitting for prose.
4. BM25 pre-filter narrows to the top candidates.
5. Embed query and candidates with `all-MiniLM-L6-v2` (384-dim, INT8 quantized) via ONNX Runtime; rank by cosine similarity.

Steps 2–4 eliminate >99% of chunks before the neural model runs. Cold query time: 468ms on a 585-file .NET codebase, 729ms on a 19k-file monorepo. No pre-indexing.

`--literal <term>` boosts files containing a specific keyword before the neural ranker runs — the escape hatch when you already know part of the vocabulary (`vex "race conditions" --literal lock --literal mutex`). `-k`, `-t`, `-g`, and `--fast` cover result count, similarity threshold, glob filtering, and binary quantization for very large trees.

## GitHub sync

`vex sync github` materializes issues and PRs as Markdown under `~/.local/share/vex/sources/github/owner/repo/` with YAML frontmatter. After that, every `vex` search includes them automatically alongside code — so "why did we change the auth flow" returns the PR discussion, the design doc, and the implementation together, ranked by relevance. Sync is incremental via `.meta/sync-state.json`; `--force` resets it.

## Getting started

[See the README](https://github.com/calumjs/vex#install) for install steps and PATH setup. The embedding model (~23 MB quantized) downloads automatically on first run.

The repo also ships a Claude Code skill that teaches the agent to use `vex` effectively — synonym expansion, follow-up queries, and flow tracing. One `vex` call typically replaces ten to fifteen grep/glob/read calls from an agent.
